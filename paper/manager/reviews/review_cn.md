## 一、编辑决定

编辑邀请进行大修，但明确表示：如果没有实质性修改，稿件很可能不会再次送审。编辑特别强调四类科学证据：

1. 更强的整体框架验证。
2. 与替代架构的比较。
3. 与其他域适配策略的公平比较。
4. 更清楚的数据集描述和真实世界泛化证据。

同时要求全文采用克制、客观的 Nature Communications 写作风格，删除 `new/novel/first/unique/superior/remarkable/pave the way` 等首创性、主观性和夸张表达。

编辑还给出了硬性合规要求：代码与软件清单、机器学习清单、色觉友好图表、Data Availability、Code Availability、Source Data、ORCID，以及逐条回复、修改标记、cover letter 和相关提交材料。

## 二、Reviewer 1

### 正面评价

Reviewer 1 认可从传统毫米波分类走向语言语义解释的研究方向，也认可毫米波在隐私友好双手交互感知中的潜力。因此该审稿人并未否定论文主问题，而是要求把成本、真实性和泛化证据补强。

### `R1-1` 补充相关工作

建议引用并讨论：

- RadarLLM，AAAI 2026。
- mmExpert，MobiHoc 2025。

### `R1-2` 训练和推理成本

4D 体素编码器与 LLM 组合可能计算开销很大，需要报告 mmPRISM 的训练成本和推理成本。

建议至少覆盖：总参数/可训练参数、训练 GPU 时间、峰值显存、FLOPs 或 MACs、batch-1 推理延迟和吞吐，并与关键 baseline 在一致硬件和输入长度下比较。

### `R1-3` 跨方向泛化

毫米波对传播路径和人体朝向敏感。当前缺少 radar-person 相对方向变化时的泛化分析，不能只假设用户始终正对、静止且严格对齐雷达。

### `R1-4a` 合成数据与真实数据的接近程度

需要直接衡量合成雷达数据与真实雷达数据的相似性，而不能只依赖下游结果说明合成数据有效。

### `R1-4b` 数据集与 split 透明度

需要说明合成数据的手语种类、动作/词汇多样性、规模、环境域，以及训练集和测试集的具体组成。

### `R1-4c` 真实数据规模与多样性

当前只有 12 名、20–30 岁志愿者，规模和人口统计多样性不足。审稿人建议利用可用手语/书写数据，并采集更多真实雷达数据。

### `R1-4d` 新用户泛化

需要证明系统能够迁移到未见用户，包括不同手型、手部大小和手势风格，而不需要大量重新训练。

### `R1-5` 双手重叠与遮挡

当两手从雷达视角发生重叠时，稀疏点云可能坍缩成一个簇。需要解释方法如何区分这种 hand-to-hand occlusion，并最好提供受控实验或失败案例。

### `R1-6` 4D cube 符号

不能只在补充材料解释 4D cube；主文中也要明确维度、符号、物理含义和张量形状。

## 三、Reviewer 2 — 论文内容

### `R2-1` 两阶段架构是否真的必要

当前优势可能来自更大容量或更强特征，而不一定来自显式姿态重建。需要加入直接端到端 baseline：将 4D voxel feature 直接送入 LLM，并对齐参数量、训练数据和训练策略，以隔离 pose bottleneck 的真实贡献。

### `R2-2` 域适配方法是否最优

当前 shallow fine-tuning 缺少横向比较。需要在相同真实数据预算下，与 full fine-tuning、adversarial domain adaptation、MMD 等方法比较，同时报告效果与效率。

### `R2-3` 真实边界场景测试

当前噪声实验仍偏实验室可控。需要同时评估姿态重建和文本翻译在以下场景的表现：

- 偏轴方向，例如 30°、60°。
- 部分手部遮挡。
- 物体遮挡。

### `R2-4` 数据集透明度

仅报告 12 subjects 和 200k frames 不够。Section 3.3 应补充：

- 手语类型。
- 词汇量。
- 句子数量。
- 平均句长。
- 非手部语法特征的覆盖情况。
- 建议进一步补充 subject、session、scene、split 和 annotation 统计。

### `R2-5` 注意力组件冗余

空间注意力、通道注意力和 SE 同时加入，容易被认为是任意堆叠。需要 leave-one-out 或单组件消融，验证每个组件的独立贡献和必要性。

### `R2-6` 跨模态 benchmark

现有 baseline 只覆盖毫米波方法。审稿人希望增加 1–2 个非接触式连续手语理解 baseline，例如 WiFi 或声学方法，使结果在更广泛无线/非视觉感知领域中有参照。

该请求存在 protocol 可比性问题：不同模态通常不共享数据、输入和采集设置。需要先确认 reviewer 期望是同数据重实现、公开 benchmark 对照，还是相关工作层面的性能定位。

## 四、Reviewer 2 — 代码可用性

### `R2-CODE-1` 硬编码本地路径

多个数据处理、仿真和工具脚本包含 `/root/autodl-tmp/...` 等本地路径，第三方无法直接运行。需要全部改为配置或 CLI 参数。

### `R2-CODE-2` 模型下载与评估链不完整

`download_models.sh` 未下载 SBERT，但 `run_evaluation.py` 强制加载 `pretrained_models/sbert`，导致官方说明路径必然失败。

### `R2-CODE-3` README/CLAUDE 与代码不一致

文档引用多个不存在的配置和 temporal/TVAN 模块。`CLAUDE.md` 被认为是内部 AI 开发说明，不应进入学术代码发布包。需要重写公开 README，并从 reviewer release archive 排除内部文件。

### `R2-CODE-4` 缺少 LICENSE

README 宣称 MIT，但仓库没有 LICENSE。必须补充真实且经作者确认的许可证文件，或修改 README 中的授权声明。

### `R2-CODE-5` Phi-3 路径不可运行

README 将 Phi-3 描述为支持/默认模型，但没有配置和运行示例，底层实现也未形成完整验证路径。需要二选一：

1. 提供完整可运行 Phi-3 train/eval 示例并修复接口；或
2. 若论文和正式 release 不需要 Phi-3，删除支持声明并明确当前只验证 mT5。

## 五、跨审稿人合并后的六个核心问题

1. **架构归因**：为什么必须经过姿态重建，而不是直接 4D radar-to-text？
2. **域适配公平性**：当前 shallow fine-tuning 是否真的优于常见 DA 策略？
3. **真实泛化**：方向、遮挡、环境和未见用户下是否仍有效？
4. **数据可信度**：合成数据与真实数据多接近，数据规模与 split 到底是什么？
5. **模块必要性与效率**：注意力组件是否必要，4D+LLM 成本是否可接受？
6. **可复现与合规**：第三方能否从下载、配置、示例数据到评测完整复现？
