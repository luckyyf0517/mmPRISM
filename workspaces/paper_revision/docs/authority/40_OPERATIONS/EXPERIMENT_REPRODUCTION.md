# Original Experiment Reproduction Runbook

Status: current
Owner: Paper revision lane
Authority scope: The manuscript revision and evidence-promotion boundary represented by this page.
Last reviewed: 2026-08-12

## 1. 固定输入

每个原投稿结果需要收集：

- manuscript table/figure/value
- original config and command
- code commit
- environment/CUDA/library versions
- dataset source, manifest and split
- checkpoint and prediction
- metric implementation/protocol

## 2. 执行顺序

1. 先重算已有 prediction 的指标，区分 metric drift 与 model drift。
2. 再用已有 checkpoint 重跑 inference，区分 preprocessing/inference drift。
3. 最后才重新训练，避免把所有差异归因于随机性。
4. 正式重训使用至少原 seed；若 reviewer 关注稳定性，再扩展多 seed。

## 3. 结果分类

- `reproduced_exact`：在严格容差内一致。
- `reproduced_with_variance`：差异可由 seed/硬件随机性解释。
- `explained_metric_drift`：指标 protocol 变化导致。
- `explained_data_drift`：数据/预处理/split 变化导致。
- `explained_code_drift`：模型或训练实现变化导致。
- `unavailable_asset`：关键数据/checkpoint 缺失。
- `unexplained_gap`：需要继续调查，不得直接写入返修结论。

## 4. 报告要求

每个结果保存 original、rerun、delta、容差、诊断、artifact 和 paper-facing decision。不得静默覆盖 manuscript 数值。

## 5. CSL-Daily Controlled Reproduction

CSL-Daily is the immediate controlled route for recovering the old camera-pose -> skeleton-simulated mmWave-pose
pipeline and for measuring translation degradation across that reconstructed cascade. It is not a substitute for
the revision's real-radar participant-disjoint, orientation, or occlusion evidence.

The controlled matrix is intentionally decomposed:

| Control | Input | Required isolation | Interpretation |
|---|---|---|---|
| `CSLD-WL-01` | accepted camera pose -> text | explicit pose-only WaveLLM; no fabricated radar feature | camera-pose semantic ceiling |
| `CSLD-WL-02` | CubeNet predicted mmWave-pose -> text | cross-fitted prediction for training rows | reconstruction-to-translation degradation |
| `CSLD-WL-03` | same predicted pose + CubeNet frame feature -> text | same pose producer, checkpoint-bound feature export | incremental encoder-feature/fusion contribution |

The first two rows require a canonical pose-only WaveLLM mode. Passing zeros to a fusion model is not a valid
pose-only baseline. For `CSLD-WL-02/03`, each primary training-row input is generated by a CubeNet checkpoint that
did not train on it; in-sample data is diagnostic-only. The candidate `annotation_v2` may replace no baseline:
`annotation_v1`, raw sidecars, failures, deterministic QC and stratified review remain preserved for comparison.

If the upload contains old CSL-Daily annotated poses, synthetic signals/cubes, or features, receipt/audit them
before regeneration. They are the first route for a direct `historical_replay`: preserve their bytes/relative
identity, bind source/caption/split and producer evidence where possible, and classify missing linkage rather than
substituting a new product. A canonical reannotation or simulation is a separate control run, not historical
reproduction by default.

Each resulting run is labelled either `synthetic_csl_daily_control`, `historical_replay`, or
`revision_real_radar`. The old CSL-Daily `val.json` and `test.json` are byte-identical, so their use is restricted
to a labelled `historical_replay/legacy_validation_as_test`; no new independent-test or generalization claim may
use them. The data and model operations are owned by their producer workspaces:
[data receipt and annotation](../../../../data_rebuild/docs/authority/40_OPERATIONS/CSL_DAILY_REPRODUCTION.md),
[OmniHand reconstruction/export](../../../../omnihand_training/docs/authority/40_OPERATIONS/CSL_DAILY_RECONSTRUCTION.md),
and [WaveLLM training](../../../../wavellm_training/docs/authority/40_OPERATIONS/CSL_DAILY_TRAINING.md).

CSL-Daily controls can support a transparent pipeline analysis and potentially explain/reproduce a historical
convention after independent asset audit. They cannot close `R1-3`, `R1-4c/d`, `R2-3`, or real-radar portions of
`R1-4a`; reviewer-facing claim promotion still requires the real-data evidence IDs and the ordinary display-item
provenance gate.
